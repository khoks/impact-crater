## Description

As a user who re-runs the same trip (a model bump, an A/B, the quality-gate runs), I want the app's disk use to stay bounded so repeated runs do not duplicate gigabytes and I can see and reclaim what it holds. Today `pipeline/stage1_ingest.py:203-207` writes thumbnails to `projects/{project_id}/cache/thumbs/{content_hash}.{256,1024}.jpg` (scene frames likewise, per project), so re-ingesting the same media into a new project duplicates ~13 GB; `~/.impact-crater` measures 92 GB (du 2026-10-24); `api/media.py:28-49` globs `*/cache/thumbs/{hash}` across all projects and serves the first match; `telemetry.jsonl` is 47 MB with no rotation (`telemetry.py` has no rotate/archive function, and the cost summary scans the whole file per job); the LLM cache (101 MB, 13,338 index rows) has no GC; the ADR-0015 "archive telemetry" Settings button was never built. The ADR-0006 design already keeps LLM payloads content-addressed — this story extends that to scene frames and thumbnails (A-027) and must land before the Phase 3 full-scale runs.

## Acceptance criteria

- [ ] Scene frames and thumbnails live in one global content-addressed store under `~/.impact-crater/cache/media/` (ADR-0006 pattern); projects reference entries (DB join row or hard link); a second ingest of the same fixture into a new project writes zero new media-cache bytes (test asserts no new files)
- [ ] A migration moves the existing per-project caches (the 24 snapshots' sidecar / thumb paths) into the shared store and rewrites DB paths; `api/media.py` resolves thumbnails by a direct content-addressed path with no cross-project glob
- [ ] Settings shows disk accounting — media cache, LLM cache, telemetry, per-project render/snapshot sizes, free disk — and a "Clean up" action that removes unreferenced cache entries and orphaned `pending` snapshots under a keep-last-N retention that never deletes a published snapshot (audit-table check)
- [ ] Telemetry rotation (size- or day-based, with an index so the per-job cost summary no longer scans the whole file) and LLM-cache GC with a first concrete rule — purge payloads for model IDs retired by S-2.10.9 — both available from `impact-crater cleanup` and the Settings button
- [ ] A Zion re-run before/after the migration yields an identical `plan.json` and adds no scene frames (dated live run in the activity log)
