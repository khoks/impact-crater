## Description

As a reviewer, I want to give feedback on the whole job ("too short overall", "great pacing") and on a phase ("the judge over-covered Grand Canyon"), not just on a single media decision — so my higher-level reactions are captured for the next session.

## Acceptance criteria

- [x] The inspect page has a "Feedback on the whole job" control and a "Feedback on this phase" control on each phase header, opening the same verdict+comment modal. — verified by frontend/src/components/DiagnosticsPanel.tsx:131-134 (job-level button, labelled "Feedback on the whole video") and :144,:201 (per-phase "Feedback on this phase"), both setting a `FeedbackTarget` that opens the shared `FeedbackModal`; live-verified in the app 2026-06-30 (activity log, PR #67) (2026-10-24)
- [ ] Job-level feedback stores with `phase="job"` (or null) and no `decision_ref`/`content_hash`; phase-level with the phase and no decision_ref. — superseded by the sentinel-ref convention shipped in PR #67: job-level stores `phase="job"`, `decision_ref="job"` and no content_hash; phase-level stores the phase, `decision_ref="phase:<phase>"` and no content_hash (frontend/src/components/DiagnosticsPanel.tsx:309-331; backend/impact_crater/api/feedback.py:35-36 keeps both columns nullable) (2026-10-24)
- [x] `scripts/feedback.py list` and the pickup flow show job/phase items distinctly. — verified by code path scripts/feedback.py:51-57: the phase column prints `job` and `ref=` prints `job` / `phase:<phase>` with no `media=` suffix, so job/phase rows read differently from decision rows, and `show` dumps the stored `context` carrying `level: "job" | "phase"` (DiagnosticsPanel.tsx:332); there is no dedicated branch for them (2026-10-24)

## Notes

Design: the `feedback` table + `/api/feedback` already accept a nullable `decision_ref`/`content_hash` and a `phase`, so the backend largely supports this already — the work is mostly frontend (DiagnosticsPanel: a job-level button near the top and a per-phase button on each `PhaseSection` header) plus a `phase="job"` convention and making `_to_item`/list render them. Reuse the existing `FeedbackModal`; pass a `target` with no `decision`. Feedback #9.
