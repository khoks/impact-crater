## Description

As a reviewer, I want to give feedback on the whole job ("too short overall", "great pacing") and on a phase ("the judge over-covered Grand Canyon"), not just on a single media decision — so my higher-level reactions are captured for the next session.

## Acceptance criteria

- [ ] The inspect page has a "Feedback on the whole job" control and a "Feedback on this phase" control on each phase header, opening the same verdict+comment modal.
- [ ] Job-level feedback stores with `phase="job"` (or null) and no `decision_ref`/`content_hash`; phase-level with the phase and no decision_ref.
- [ ] `scripts/feedback.py list` and the pickup flow show job/phase items distinctly.

## Notes

Design: the `feedback` table + `/api/feedback` already accept a nullable `decision_ref`/`content_hash` and a `phase`, so the backend largely supports this already — the work is mostly frontend (DiagnosticsPanel: a job-level button near the top and a per-phase button on each `PhaseSection` header) plus a `phase="job"` convention and making `_to_item`/list render them. Reuse the existing `FeedbackModal`; pass a `target` with no `decision`. Feedback #9.
