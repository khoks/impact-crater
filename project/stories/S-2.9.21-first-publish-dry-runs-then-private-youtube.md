## Description

As the owner, I want the app's publish path proven end to end — first as a dry-run on every shipped connector, then as one real private YouTube upload — so that the D-014 publish half (the only open MVP pre-flight gate, `docs/roadmap/MVP.md` #2 per D-057) closes with an audit row and a URL. Restart plan Phase 1 item 4 (`docs/roadmap/LANDSCAPE-AND-PLAN-2026-10-24.md` §5): "one dry-run per platform through the UI (three `(dry-run)` audit rows), then owner-side: mint `IC_YOUTUBE_*`, dry-run off, publish … at `private`, confirm the audit row and URL, flip dry-run back."

## Notes

The preview page with Approve & publish is keyed by a live job ID and the job registry is in memory (S-2.9.19), so a snapshot from before a server restart cannot be published through the UI until SnapshotInspect gains Approve & publish (S-3.5.5). The dry-runs therefore run on a fresh Zion job whose AI calls are all cache hits.
