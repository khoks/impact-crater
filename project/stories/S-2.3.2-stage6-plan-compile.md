## Description

Per ADR-0011 Stage 6 (without orchestrator second-guess — that lands in M6) — walk the `ArcJudgment.selected_items`, compute final clip durations, insert simple cuts (no music-video beat-snap; music-video lands in M4), validate against target_duration, run smart-crop where needed, and persist as `snapshots/{snapshot_id}/plan.json` per ADR-0006.

Standard mode only at M2; music-video mode = `NotImplementedError("M4")` so attempts to use it fail loudly rather than silently.

## Acceptance criteria

- [x] `backend/impact_crater/pipeline/stage6_plan.py` — `compile_plan(arc_judgment, ingest_records, *, project_id, target_duration_seconds, mode, audio, parent_snapshot_id) → RenderPlan` (async — owns the snapshot DB write)
- [x] `RenderPlan` Pydantic model with ordered `clips` (RenderClip with candidate_ref, kind, source_path, start/end_seconds, intended_duration_ms, aspect_ratio_action, transition_in, role, notes)
- [x] Aspect-ratio decisions: `as_is` (within 10% of 16:9), `smart_crop` (portrait photo / landscape >16:9 video), `letterbox` (portrait video). Smart-crop *integration* (saliency CNN via `smartcrop.py`) deferred to render time in S-2.3.3 — at M2 the action is recorded; `letterbox`/`pad` ffmpeg filters cover the obvious cases and `smart_crop` falls back to a center-crop.

- [x] Snapshot creation: `~/.impact-crater/projects/{project_id}/snapshots/{snapshot_id}/plan.json` + DB row in `snapshots` table (`render_status='pending'`)
- [x] `load_plan(snapshot_id, project_id)` round-trips back to a typed RenderPlan
- [x] `mode="music_video"` raises NotImplementedError loudly (M4 scope)
- [x] `tests/test_stage6_plan.py` (13 tests) — photo/video resolution, ref skipping, ordering, aspect actions, duration scaling, persistence + DB row, load round-trip, music spec, mode validation, zero-clip raise
