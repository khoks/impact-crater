## Description

As the user validating the MVP on real trip media (33 Zion Canyon Overlook photos + 1 video + Gimme Shelter mp3), I want jobs to stop failing with `stage4_empty_candidate_set` and renders to come out watchable in both modes, so D-014 validation can proceed.

Four bugs found and fixed during the 2026-06-11 manual test session (both standard and music_video modes tested end-to-end via `POST /api/jobs/submit`, renders evaluated frame-by-frame + audio-probed):

1. **LLM cache payload-path collision (root cause of the user's failed job):** payload filenames omitted `params_canonical`, so quality + per-brief narrative scores for one photo overwrote a single file; "quality" cache hits returned stale narrative scores → all 36 assets fell below the 0.40 floor. Fixed + poisoned rows purged via migration. PR #35, D-040.
2. **Music-video timeline truncation:** one-clip-per-beat-interval snap rendered 25.3s of a 60s target. Boundaries now snap to beat cuts after scaling to target. PR #36, D-041.
3. **Audio fade-out never played:** trim/fade computed against `target_duration_ms` while the mux is `-shortest`; now computed against the actual summed timeline (−19→−39 dB measured fade in retest). PR #36.
4. **EXIF orientation ignored:** portrait phone photos (Orientation=6) ingested with stored landscape dims → `as_is` aspect action → pillarboxed sideways-looking clips; thumbnails + Anthropic re-encodes reached vision LLMs sideways. `ImageOps.exif_transpose` at ingest + in `_fit_image_for_anthropic`. PR #36.

Also: `scripts/windows/start.ps1` one-shot dev launcher (PR #37). Stage4EmptyCandidateSet message now reports the quality-score range and flags all-zeros as an app bug.
