## Description

As a user who dumps a multi-location trip, I want — besides the full-journey video — one short vertical Reel per place I visited (Zion, Bryce, Horseshoe Bend…), each ≤ 90 s and ready for Instagram Reels or YouTube Shorts, so the "multiple reels highlighting the locations" from the original vision starts arriving without waiting for the whole Trip Package. This is the **first concrete multi-artifact deliverable** in the restart plan (Phase 4) and the single artifact type; S-3.2.3 is the orchestration that will later decide how many artifacts a source set deserves. Today every output is 16:9: `RenderPlan.output_aspect` is `Literal["16:9"]` and `output_width/height` default to 1920×1080 (`pipeline/stage6_plan.py:154-156`) but Stage 7 never reads them — `pipeline/stage7_render.py:78-79` uses the module constants `_OUT_W = 1920`, `_OUT_H = 1080` in every filter chain, and `smart_crop` is a centre-crop (`stage7_render.py:358-364`), so portrait video is letterboxed and a vertical cut of a landscape shot would lose the subject.

## Acceptance criteria

- [ ] Prerequisite landed (S-3.3.3): Stage 7 honours `RenderPlan.output_width / output_height / output_aspect` (the fields stop being dead; `_OUT_W / _OUT_H` are removed) with a saliency-aware crop for 9:16 (face / subject bbox from the Stage 3 or cast data, centre as fallback), and per-platform duration caps are enforced at plan time (Reels ≤ 90 s, Shorts ≤ 60 s) rather than discovered when the Graph API container fails.
- [ ] Location detection: assets are grouped into locations from GPS clusters, `location_description` and the brief's named destinations (`pipeline/destinations.py` — text-only today; `reverse_geocoder` is not installed), with a minimum-media floor below which a location gets no reel (documented default, overridable).
- [ ] For each location above the floor the pipeline produces a `reel` artifact: its own `RenderPlan` (9:16, `target_duration_ms ≤ 90 000`, music fitted to the shorter cut, title card optional) rendered to `reels/<location-slug>/render.mp4` beside the main `render.mp4`, with its own `cost_summary.json` + `diagnostics.json`; the judge call is scoped to that location's kept set (no second full-set judge).
- [ ] Preview lists the reels under the main video with per-reel approve / refine / publish (same gate; approving the video never publishes a reel); publish targets are Instagram (S-3.3.1) and YouTube as Shorts (vertical + ≤ 60 s is what makes a Short — the connector sets nothing special, but the duration cap must be the Shorts one when YouTube is the target).
- [ ] Budget: the reels' Tier-L judge calls are counted in the pre-job estimate and the mid-job cap guard; a job's cost preview shows "+ N reels" with the delta.
- [ ] Tests: 9:16 filter chain and crop bbox (`tests/test_stage7_render.py`); location grouping + floor on the SW-US fixture (`tests/test_destinations.py`); reel plan duration cap; artifact listing in the projects / snapshots API; vitest for the per-reel actions.

## Notes

- Start deterministic: one location → one reel, kept set scoped by location, judge prompt reused with a "60–90 s vertical highlight" framing. Density-driven allocation (which locations deserve a full video vs a reel vs a merge) is E-4.5 / S-3.2.3, not this story.
