## Description

As a user refining a video ("make the Vegas part shorter"), I want the refine to run like a job — progress, a cancel button, a cost check before it spends — and I want the refined version to be a first-class result I can approve, publish or refine again, so the refine loop is actually the "preview → adjust → approve" flow the product promises rather than a one-shot detour.

Today `POST /api/snapshots/{id}/refine` (`backend/impact_crater/api/snapshots.py:161-199`) is one synchronous HTTP call: it builds the router, runs `execute_refinement` (re-judge + re-render inline — 2 m 11 s on a small project) and only then answers; there is no quota pre-check (the job runner's `quota.check_quota` at `pipeline/runner.py:178` is not on this path), no progress event and no cancel. The child snapshot written by `pipeline/stage9_refine.py:422` holds only `plan.json` + `render.mp4` — no `cost_summary.json` or `diagnostics.json`, so refinement cost is unpersisted and `GET /diagnostics` answers "this snapshot predates the feature" (`api/snapshots.py:78-83`). `frontend/src/routes/SnapshotInspect.tsx` has no Approve, Publish or Refine controls, `api/projects.py` does not return `parent_snapshot_id` although the `snapshots` table stores it (`stage6_plan.py:813-816`), and no frontend file references a parent snapshot — so a child cannot be published or refined again from the UI. Plan Phase 1 item 7 (publish from any snapshot) and Phase 2 item 4 (refinement as a job).

## Acceptance criteria

- [ ] `POST /api/snapshots/{id}/refine` returns **202** with a `job_id` and `websocket_url`; progress streams over the existing `/api/jobs/ws/{job_id}` sink (stage events for interpret → re-judge → re-render); `POST /api/jobs/{job_id}/cancel` stops it between stages and leaves no half-written child snapshot.
- [ ] A quota pre-check runs before any paid call, sized by whether the interpreted directive needs a re-judge (Tier-L) or only a directive patch + re-render ($0); a blocked check returns the same shape as the job-submit refusal.
- [ ] Child snapshots are complete artifacts: `plan.json`, `render.mp4`, `cost_summary.json`, `diagnostics.json`, `refinement_plan.json`, plus `second_guess.json` when produced; the Dashboard sums child costs into the project total.
- [ ] `SnapshotInspect` becomes the canonical preview: **Approve & publish** (same modal and connectors as `JobPreview`) and **Refine** work on any snapshot, parent or child; `JobPreview` either redirects there once a snapshot exists or shares the same component.
- [ ] `GET /api/projects` returns `parent_snapshot_id` per snapshot; the Dashboard shows the refine chain (parent → children, newest first) and which snapshot, if any, was published.
- [ ] Tests: 202 + WS progress + cancel for refine (`tests/test_api_refine.py`); quota refusal path; child artifact files present after a refine (`tests/test_stage9_refine.py`); `parent_snapshot_id` in the projects response; vitest for the chain and the Inspect actions.
