## Description

As the developer, I want two in-app pages to visualize and steer the work:
a feedback/enhancement tracker (every in-app feedback item with full
context + screenshot, editable status + priority) and a workplan tracker
(the Initiative→Epic→Story→Task plan with status/phase, editable priority).

## Acceptance criteria

- [x] `/feedback` — priority-sorted, status-filterable list; per-item detail with job/project/snapshot, phase + decision_ref, the decision context (media thumb + scores + reason), the whole phase's decision strip (from snapshot diagnostics, flagged shot highlighted), embedded page screenshot; editable status + priority (PATCH)
- [x] `/workplan` — Initiative→Epic→Story→Task hierarchy, status + phase badges, status/phase rollups, editable priority; status read-only (markdown canonical), priority via overrides reconciled by work-tracker
- [x] Backend: feedback `priority` column + detail/PATCH; `api/workplan.py` (markdown parser + overrides); migration 006; routers registered
- [x] Dashboard nav links; tests (backend + frontend); verified live in Chrome (90 work items parsed; feedback detail with screenshot; override round-trip)

## Dependencies

- Builds on: S-2.9.8 (feedback loop), ADR-0002 (work hierarchy)

## Notes

Workplan status stays read-only in-app (work-tracker owns the markdown);
priority overrides are surfaced at `GET /api/workplan/overrides` + the
CLAUDE.md pickup note for reconciliation.
