## Description

As a user whose trip media is full of strangers, I want to see the cast the app inferred — who it thinks is "the group" and who is crowd — name them, promote or demote anyone it got wrong, and fix "Priya appears in 0 selected clips" with one click, so the people who matter are in the video and the cast's mistakes are mine to correct rather than silently baked in. The analysis half of A-018 shipped on 2026-06-11 (D-044): `backend/impact_crater/media/cast.py` detects, embeds, clusters, splits group / crowd and computes a `CoverageReport`, and the Inspect page's diagnostics show a read-only "Trip cast" phase (`frontend/src/components/DiagnosticsPanel.tsx:452,487`). The review half never landed: no naming, no promote / demote, no coverage repair, and the settings that drive it — `cast_analysis_enabled`, `cast_backend` (`gemini` | `insightface`), `image_embed_backend` (`storage/settings.py:26-30`) — have no Settings UI, so the D-044 "config flip" means editing the SQLite settings table by hand. Plan Phase 3 item 5.

## Acceptance criteria

- [ ] Inspect gains a **Cast** tab: each inferred person as a face-crop strip with appearance count, days and locations; actions **Name**, **Promote to group**, **Demote to crowd**, **Merge with…**; edits persist per project (`persons` / cast tables) and are applied on the next run and on refine without re-clustering.
- [ ] Coverage repair: for each group member with zero (or below-floor) selected clips, a one-click **Include <name>** that reserves that person's best asset(s) through the existing reservation seam (`PreFilterOverrides` must-keeps / `PlanDirective`) and triggers a refine; the result shows the before / after coverage.
- [ ] Settings exposes `cast_analysis_enabled` (toggle), `cast_backend` and `image_embed_backend` (pickers that list only installed backends, with the insightface licensing note) — no more hand-editing the settings table; the API validates the values the pipeline already accepts (`api/jobs.py:45 _resolve_cast_settings`).
- [ ] N-008 decision measured, not asserted: run the auto cast on ≥ 3 known persons across a real trip, record precision / recall per person in this activity log, and decide whether the auto cast supersedes N-008's manual library (S-2.6.2) — on yes, cancel S-2.6.2 with the evidence and make the People page (`PersonLibrary.tsx`) the naming layer over the auto cast; on no, wire the collage into Stage 3 as S-2.6.2 says.
- [ ] Tests: cast edit persistence and re-application (`tests/test_cast.py` / `tests/test_persons_api.py`); coverage-repair reservation on a fixture; vitest for the Cast tab actions; settings validation for the three keys.

## Notes

- A-018's own text names this remainder: "coverage-repair UI + person naming + the v1.8 LLM-driven refinements remain"; the LLM-driven refinements stay out of this story.
- Face crops and embeddings are `face_data` under ADR-0016; the Cast tab must render crops from local renditions only and the privacy copy must say what the chosen `cast_backend` sends (Gemini embedder = remote).
- Local backends (`insightface`, `torch`, `onnxruntime`, `open_clip`) are not installed on the dev machine, so `cast_backend=insightface` degrades to the Gemini embedder today; the backend picker must show that state rather than pretend.
