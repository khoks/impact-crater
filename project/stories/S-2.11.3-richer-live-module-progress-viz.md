## Description

As a user watching a job run, I want to see the individual modules and decisions executing — at the depth of the pipeline infographic — not just "Step N of 7", so I understand and trust what the AI is doing.

## Acceptance criteria

- [x] The live job view expands each of the 7+ stages into its sub-modules (e.g. Stage 1: hash → capture-time → GPS → scene-detect → thumbnails; Stage 4: safety → min-video → quality → pHash → semantic-dedup → location-cap → rank; Stage 5: candidate count, then selection). — verified by frontend/src/routes/JobInProgress.tsx:68-120 (`STAGE_SUBMODULES` lists sub-modules for all 7 stages; rendered as chips at :624-630 for the active/completed stage); live-verified in the app 2026-06-30 (activity log, PR #67). No unit test covers the chips — frontend/src/__tests__/JobInProgress.test.tsx asserts only the 7 stage rows (2026-10-24)
- [ ] Per-stage live counters (e.g. "caption 1240/1663", "kept 621/2068", "selected 48") stream from the existing `JobProgressEvent` / per-phase diagnostics (A-023) rather than new backend work where possible. — deferred → v1 (E-3.5 power-user + polish bundle): only Stage 2 has a live counter (`N/M shots analyzed · P%`, derived from llm_call cache events — JobInProgress.tsx:213-225,556-564); Stages 1 and 3–7 show the backend's end-of-stage `detail` string only (e.g. `621/2068 candidates`, `N clips` — backend/impact_crater/pipeline/runner.py:218-314,609-618), not streaming counters (2026-10-24)
- [x] As each phase's diagnostics arrive, its decision cards stream into the live view (the `DiagnosticsView` already supports this). — verified by frontend/src/routes/JobInProgress.tsx:185 and :783 (`diagnostics` events fill `livePhases`) and :495-512 (the "Decisions so far" section renders `DiagnosticsView` from `livePhases` while the job runs); live-verified 2026-06-30 (activity log, PR #67) (2026-10-24)

## Notes

Design: the backend already emits `JobProgressEvent`s (state/stage/llm_call/render/diagnostics) over `/api/ws/jobs/{id}` and streams per-phase diagnostics (A-023). The work is mostly a frontend redesign of `JobInProgress` to render a module tree with live counters and to fold in the streaming `DiagnosticsView`. Add finer per-substep progress events where the current granularity is too coarse (e.g. Stage 1/2 per-asset counters). Feedback #10.
