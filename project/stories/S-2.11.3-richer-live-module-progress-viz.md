## Description

As a user watching a job run, I want to see the individual modules and decisions executing — at the depth of the pipeline infographic — not just "Step N of 7", so I understand and trust what the AI is doing.

## Acceptance criteria

- [ ] The live job view expands each of the 7+ stages into its sub-modules (e.g. Stage 1: hash → capture-time → GPS → scene-detect → thumbnails; Stage 4: safety → min-video → quality → pHash → semantic-dedup → location-cap → rank; Stage 5: candidate count, then selection).
- [ ] Per-stage live counters (e.g. "caption 1240/1663", "kept 621/2068", "selected 48") stream from the existing `JobProgressEvent` / per-phase diagnostics (A-023) rather than new backend work where possible.
- [ ] As each phase's diagnostics arrive, its decision cards stream into the live view (the `DiagnosticsView` already supports this).

## Notes

Design: the backend already emits `JobProgressEvent`s (state/stage/llm_call/render/diagnostics) over `/api/ws/jobs/{id}` and streams per-phase diagnostics (A-023). The work is mostly a frontend redesign of `JobInProgress` to render a module tree with live counters and to fold in the streaming `DiagnosticsView`. Add finer per-substep progress events where the current granularity is too coarse (e.g. Stage 1/2 per-asset counters). Feedback #10.
