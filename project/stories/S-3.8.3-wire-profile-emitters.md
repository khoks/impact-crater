## Description

As a returning user, I want the app to actually remember what I approved, refined, published or cancelled, so that the cross-project profile (N-010) stops being an empty backend and my next project starts from what I liked. Today `profile.py` exposes `emit()`, `derive_profile()`, `reset()` and `suggestions_for_new_job()`, and `api/profile.py` mounts four endpoints (`GET /snapshot`, `POST /derive`, `POST /reset`, `POST /feedback`), but no module outside `profile.py` / `api/profile.py` calls `emit`, `frontend/src` has zero references to the profile, and the profile has never been derived (grep 2026-10-24; `~/.impact-crater/profile/` exists but holds no derived profile). E-2.9 marked the MVP profile delivered on the strength of the backend alone (landscape §3). Per the restart plan this story carries two halves with two acceptance groups: the emitters + derivation (Phase 2 item 14) and the UI half (Phase 4 "profile UI"), kept in one story so neither half is forgotten.

## Acceptance criteria

Group A — emitters and derivation (Phase 2):

- [ ] Events are emitted from the real code paths — approve/publish (`api/publish.py`), refine (`api/snapshots.py` refine route / Stage 9), cancel (`POST /jobs/{id}/cancel`), and effort-level override at job submit (`api/jobs.py`) — each carrying project_id, snapshot_id, brief hash and the decision payload; a test per path asserts exactly one event with a stubbed sink
- [ ] `derive_profile()` runs at job end (runner glue, after the snapshot is written) and after approve/publish; a derivation failure is logged and never fails the job or the publish
- [ ] After one Zion smoke job + one approve, `~/.impact-crater/profile/` holds event lines and a derived profile; `GET /api/profile/snapshot` returns it (dated live run recorded in the activity log)

Group B — UI half (Phase 4, with S-3.8.2):

- [ ] New Project pre-fills brief hints / effort level from `suggestions_for_new_job()` and says where they came from; Settings has "Reset what you've learned" calling `POST /api/profile/reset` with confirmation; both covered by vitest
