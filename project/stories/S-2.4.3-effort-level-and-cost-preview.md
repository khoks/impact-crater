## Description

Per D-013 + ADR-0015 §"UI surfaces" — the user sees pre-canned effort levels (L1 / L2 / L3) with the agentic max-permissible recommendation and a transparent cost preview. Going past max-permissible triggers an upgrade-path explanation.

The L_max recommendation logic is deterministic at M3: backend computes `fits_today_budget` per level from the current `quota_state`. The agentic explanation prose lands in v1 (per A-015's "agentic explanation" classification).

## Acceptance criteria

- [ ] `frontend/src/routes/EffortAndCost.tsx` — receives the new-project form data via route state
- [ ] Renders 3 cards (L1, L2, L3) with: photo cap / video cap / estimated cost range / "fits today's budget" badge
- [ ] Default selection = the highest level that fits the budget (L_max)
- [ ] Per-tier cost breakdown panel: Embeddings / Tier-S / Tier-M / Tier-L estimates against today's remaining
- [ ] If user picks a level whose ceiling exceeds their submitted media count, surfaces a warning
- [ ] If user's media count exceeds L_max's photo cap, surfaces an "upgrade your spend cap or use fewer photos" hint
- [ ] "Start Job" button submits via `POST /api/jobs/submit` and routes to `/jobs/:id`
- [ ] `frontend/src/__tests__/EffortAndCost.test.tsx` — level rendering, default selection, submit navigation
