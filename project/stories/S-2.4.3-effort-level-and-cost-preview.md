## Description

Per D-013 + ADR-0015 §"UI surfaces" — the user sees pre-canned effort levels (L1 / L2 / L3) with the agentic max-permissible recommendation and a transparent cost preview. Going past max-permissible triggers an upgrade-path explanation.

The L_max recommendation logic is deterministic at M3: backend computes `fits_today_budget` per level from the current `quota_state`. The agentic explanation prose lands in v1 (per A-015's "agentic explanation" classification).

## Acceptance criteria

- [x] `frontend/src/routes/EffortAndCost.tsx` — pulls draft from `useNewProjectStore`; bounces back to `/projects/new` if no draft is staged
- [x] Renders 3 LevelCard tiles (L1/L2/L3) with photo_cap / video_cap / cost range / "fits today's budget" badge / `recommended` flag
- [x] Default selection = `recommended_level_id` from the API (L_max)
- [x] Per-tier cost breakdown panel below the cards: Embeddings / Tier-S / Tier-M / Tier-L estimates against `today_remaining_usd`
- [x] UpgradeHint surfaces when media count exceeds the picked level's photo+video cap with copy "raise your spend cap in Settings if needed or use a smaller folder"
- [x] "Start Job" button → `POST /api/jobs/submit`; on 202 resets the draft + routes to `/jobs/:job_id`. Disabled when budget doesn't fit (with explanatory amber banner).
