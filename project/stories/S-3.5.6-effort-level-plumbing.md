## Description

As a user choosing an effort level before submit, I want the level I pick to change what the pipeline does — how many assets survive the pre-filter, which tier judges them, how long it takes — so the cost range I am shown is the cost of the job I get. Today the picker is cosmetic: `frontend/src/routes/EffortAndCost.tsx` keeps `selectedId` and sends it only to the cost preview (`CostPreviewRequest.level_id`, `backend/impact_crater/api/effort.py:135-138`); `SubmitJobRequest` (`api/jobs.py:280-290`) has no level field, so the pipeline runs identically at L1, L2 and L3 and the per-level photo / video caps and tier choices D-013 describes are never applied. The restart audit lists this under "claimed done vs what runs". Plan Phase 2 item 6, paired with S-2.9.18 (token-aware pre-job estimate).

## Acceptance criteria

- [ ] Decision recorded in this story (and as a D-NNN if it changes D-013): **plumb** the level or **collapse** the picker. Default: plumb.
- [ ] If plumbed: `SubmitJobRequest.level_id` is validated against `api/effort.py`'s levels and mapped to `PreFilterOverrides` (`pipeline/stage4_prefilter.py:65` — `target_size`, `quality_threshold`, montage / dedup knobs) and to routing overrides (judge tier, Stage 3 model) on `RunnerConfig`; the level is persisted on the job / snapshot (`cost_summary.json`) and shown in Inspect; a job at L1 vs L3 on the same fixture produces different kept-set sizes in a test.
- [ ] If collapsed: the three cards become a single budget confirmation that shows the token-aware range from S-2.9.18, `recommended_level_id` logic is removed, and D-013 is amended to say why.
- [ ] Either way the cost preview and the submitted job use the same inputs, so the preview range brackets the actual `cost_summary.json` total within the S-2.9.18 tolerance (±30 %) on the Zion fixture.
- [ ] Tests: `tests/test_api_effort_levels.py` covers level → overrides mapping (or the collapsed response); `tests/test_api_jobs.py` rejects an unknown `level_id`; vitest confirms the picker's selection reaches the submit payload.
