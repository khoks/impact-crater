## Description

Per ADR-0010 + ADR-0011 Stage 1 — given a list of media paths, compute SHA-256 content hashes, populate the `media` + `project_media` SQLite tables, generate 256+1024 px thumbnail variants, and (for video) run PySceneDetect to produce a per-scene list with 3 representative frames per scene. Photo decode = Pillow + pillow-heif. Video decode/probe = ffmpeg-python.

## Acceptance criteria

- [ ] `backend/impact_crater/pipeline/stage1_ingest.py` — `ingest_media(project_id, paths)` returns list of media records
- [ ] Content-hash via `hashlib.sha256` on file bytes
- [ ] Photo decode covers JPEG/PNG/WebP + HEIC; pHash + dHash via `imagehash`
- [ ] Video decode probes container/codec/duration/fps via ffprobe; PySceneDetect ContentDetector with 50/video cap; 3 frames per scene as PNG in cache
- [ ] Idempotent — running ingest_media twice on the same paths is a no-op (rows already exist)
- [ ] `tests/test_stage1_ingest.py` — synthetic + bundled fixtures cover photos + 1 short video
