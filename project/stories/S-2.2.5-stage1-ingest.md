## Description

Per ADR-0010 + ADR-0011 Stage 1 — given a list of media paths, compute SHA-256 content hashes, populate the `media` + `project_media` SQLite tables, generate 256+1024 px thumbnail variants, and (for video) run PySceneDetect to produce a per-scene list with 3 representative frames per scene. Photo decode = Pillow + pillow-heif. Video decode/probe = OpenCV (via scenedetect's default backend); ffmpeg-python is reserved for Stage 7 render in a later epic.

## Acceptance criteria

- [x] `backend/impact_crater/pipeline/stage1_ingest.py` — `ingest_media(project_id, paths)` returns list of media records
- [x] Content-hash via `hashlib.sha256` on file bytes (1MB streaming)
- [x] Photo decode covers JPEG/PNG/WebP + HEIC (pillow-heif registered); pHash + dHash via `imagehash`; 256/1024 thumbnails written to project cache
- [x] Video decode probes width/height/fps/duration via cv2; PySceneDetect ContentDetector with 50/video cap (configurable); 3 frames per scene as PNG in cache; scenes.json sidecar
- [x] Idempotent — running ingest_media twice on the same paths is a no-op (INSERT OR IGNORE on `media` + `project_media`)
- [x] `tests/test_stage1_ingest.py` — synthetic JPEG/PNG photos + cv2-generated synthetic MP4 video; 12 tests covering hashing, classification, photo path, video path, idempotency, scene cap, error skips
