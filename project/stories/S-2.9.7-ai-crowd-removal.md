## Description

As a user with tourist-site photos full of strangers, I want to remove the
crowd from selected shots so the artifact is cleaner. Builds directly on
the A-018 cast (it supplies the identity of who is "crowd" vs "group").

Design locked by **D-044**: pluggable backend behind a `CrowdRemover`
interface + factory, configured via a `crowd_remover_backend` setting.
- **Default `remote`** — a remote image-editing API does the inpaint.
- **Optional `local`** — on-device LaMa/SDXL-class inpainting for capable
  machines (no faces leave the device).

## Acceptance criteria

- [ ] `CrowdRemover` interface + factory; `remote` default + `local` optional, selected via `crowd_remover_backend`
- [ ] Segmentation mask of non-cast people per photo (A-018 supplies cast identity; mediapipe/person-segmentation supplies the mask)
- [ ] Opt-in per-photo edit in the refine loop — NEVER auto-applied; edited copies live beside originals in the snapshot (N-003 immutability; never overwrite source media)
- [ ] Before/after preview + per-photo accept/reject in the UI
- [ ] Privacy posture under ADR-0016: the remote default sends full-res face-bearing crops off-device — surfaced explicitly to the user before first use; local backend keeps everything on-device
- [ ] Edits disclosed in publish metadata (authenticity)
- [ ] Tests for the interface + mask logic; backend calls mocked

## Open decisions before build

- **Which remote image-editing API** (and its key/cost model) is the `remote` default — a concrete provider choice, analogous to how the connectors pick a platform API.
- Quality bar for inpainting at full resolution; cost per edit.
