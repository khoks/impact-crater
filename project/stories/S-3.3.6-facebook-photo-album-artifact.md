## Description

As a user who dumps a trip's media and asks for "the video and a Facebook post with 20 plus photos", I want the same curation pass that builds my video to also produce a photo album I can review, trim and approve, then publish as a single Facebook multi-photo Page post — so the album is one more approved artifact, not a second afternoon of picking photos. This is an original vision item (`docs/vision/RAW_VISION.md`: "I want to create a Facebook post with 20 plus photos") that had no tracker item until the 2026-10-24 restart audit; the plan schedules it in Phase 4 ("photo-album artifact + Facebook multi-photo post").

## Acceptance criteria

- [ ] A second artifact type `photo_album` is produced from the Stage 4 / 5 kept set without a new analysis pass: photos only, ordered by narrative beat then capture time, dedup-aware (one per burst / retake cluster), ≥ 20 when the kept set allows, with a configurable cap; named destinations from the brief are each represented when media exists (reusing the S-2.10.5 coverage plan).
- [ ] The album is written beside `render.mp4` under the snapshot as `album/` (ordered, re-encoded renditions with EXIF stripped via `media/privacy.py`, which has zero call sites today) plus `album.json` (order, source `content_hash`, per-photo caption / alt-text slots for S-3.3.7) and is listed by the projects / snapshots API as an artifact of that snapshot.
- [ ] The preview page shows the album grid under the video with per-photo remove and drag-to-reorder; the approve gate applies per artifact (approving the video does not publish the album).
- [ ] `FacebookConnector` gains `upload_album()`: each photo uploaded unpublished (`POST /{page_id}/photos`, `published=false`), then one `POST /{page_id}/feed` with `attached_media` and the message; dry-run default; one audit row per album publish with the post permalink; Facebook's per-post photo limit enforced in validation.
- [ ] Tests: album builder determinism and ordering on a fixture plan; stub-transport test of the two-step multi-photo flow; frontend test of remove / reorder.

## Notes

- Everything above the connector is deterministic — no new LLM op is needed for the first version; the judge's beats and the Stage 4 keepers already carry the ordering signal. A Tier-S "pick the album cover + write the message" call can come with S-3.3.7.
- Photos leave the machine at full resolution for the first time here: strip EXIF (GPS included) at the rendition point and say so in the "What we send" copy (plan Phase 2 item 7).
- Facebook multi-photo posts have a per-post photo ceiling and the Page Photos endpoint accepts inline multipart like the video endpoint, so no `IC_PUBLIC_BASE_URL` is needed.
