## Description

As a user installing the app from PyPI, I want `pip install` in a fresh virtualenv to give me a working app, so that no git checkout is needed. Today an installed wheel cannot route a single LLM call: `llm_clients/prompts.py:24` resolves `prompts/` and `llm_clients/router.py:51` resolves `config/llm-routing.yaml` as `Path(__file__).resolve().parents[3]` (the repo root), `rate_cards.py:24` resolves `config/rate-cards/` as `parents[2]`, and `api/workplan.py:46` reads `project/` the same way; none of these directories is in `[tool.setuptools.package-data]` (`pyproject.toml:92-96` lists only `storage/migrations_sql/*.sql` and `frontend_dist/**/*`). `requires-python = ">=3.11"` (`pyproject.toml:10`), ruff `target-version = "py311"` (:100) and mypy `python_version = "3.11"` (:115) disagree with every doc, which assumes 3.12; version `0.0.1` is duplicated in `pyproject.toml:7`, `frontend/package.json:4` and `backend/impact_crater/__init__.py:6`; there is no `CHANGELOG.md` and zero git tags across 80 commits (77 PRs). Restart plan §5 Phase 2 item 9b and Phase 1 item 9; landscape §4.3 #40.

## Acceptance criteria

- [ ] `prompts/`, `config/llm-routing.yaml` and `config/rate-cards/*.yaml` ship inside the wheel — moved under `impact_crater/` (default) or declared as package-data — and are resolved through `importlib.resources` in `prompts.py`, `router.py` and `rate_cards.py` (env-var overrides kept); `api/workplan.py` degrades gracefully when `project/` is absent (developer pages only)
