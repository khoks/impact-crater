## Description

Jobs are held only in the in-memory `JobRegistry`, so after a server (or
computer) restart the live `/jobs/:id` and `/jobs/:id/preview` views are gone —
and with them the only UI route to a finished render's per-phase diagnostics +
feedback. But the render, plan, and **diagnostics are all persisted** (the
diagnostics API is keyed on `snapshot_id`, and `POST /api/feedback` accepts
`snapshot_id` + `project_id` with `job_id` optional). So a user who restarts
could no longer give feedback on a completed job without paying to re-run it.

Fix: a small snapshot-keyed route that reaches the persisted data directly.

## Acceptance criteria

- [x] New route `/snapshots/:snapshot_id/inspect` (`SnapshotInspect.tsx`) renders the saved render (`/api/snapshots/:id/render.mp4`) + `DiagnosticsPanel` keyed on `snapshot_id` (+ `project_id` from `?project=`). No in-memory job needed.
- [x] Dashboard adds an **"Inspect & feedback"** link on every persisted snapshot → the new route. Restores reviewability for *all* past jobs after a restart.
- [x] Reuses existing pieces: `DiagnosticsPanel` already supported snapshot-only mode; `FeedbackRequest` already makes `job_id`/`project_id`/`snapshot_id` optional (only `phase`+`verdict` required).
- [x] Verified live in Chrome on the SW-US-trip snapshot (b4b73c7b1fe044b7): 4 phases / 2,327 decisions loaded, opened a decision, submitted real feedback → persisted ("1 piece of feedback saved").

## Dependencies
