## Description

As a user approving a video, I want the title, description, hashtags, alt text and a subtitle sidecar already drafted and editable in the Approve modal so publishing is a one-minute review, not a writing task — and so the published video is accessible by default. `docs/roadmap/MVP.md` constraint #16 ("Auto-captions (MVP-lite): generated at curation; user reviews pre-publish", A-009) has **zero code** today: a grep of `backend/impact_crater` and `frontend/src` for subtitle / `.srt` / hashtag hits only an unrelated string in `connectors/instagram.py`, and the Approve modal's title / description are typed from scratch. Plan Phase 4 "captions MVP-lite (description, hashtags, alt text, `.srt`)".

## Acceptance criteria

- [ ] A routed `generate_publish_copy` op (Tier-S or Tier-M in `config/llm-routing.yaml`, with a rate card and an integrity-test entry) takes `plan.json`, the Stage 3 per-asset captions, the brief / `BriefIntent`, the title card and the target platform, and returns a schema-validated `PublishCopy{title, description, hashtags[], alt_text, scene_captions[{start_ms, end_ms, text}]}`; cached per ADR-0006 on the plan hash + model; fail-soft (empty copy → blank fields, publish still works).
- [ ] `captions.srt` is generated from `scene_captions` timed to each `RenderClip`'s start / duration (visual scene captions — no speech transcription in MVP-lite), and `publish_copy.json` + `captions.srt` are written beside `render.mp4`; refine child snapshots get their own (S-3.5.5 makes child artifacts first-class).
- [ ] The Approve modal pre-fills title, description, hashtags and alt text from `publish_copy.json`, all editable, with per-platform caps shown (YouTube title ≤ 100 chars; Instagram ≤ 30 hashtags; X post length); edits are saved back to the snapshot and are exactly what the connector sends.
- [ ] `YouTubeConnector` uploads `captions.srt` as a caption track (`captions.insert`, 400 quota units) after the video insert and records it in the audit row; Instagram / Facebook receive the caption text in the post (no sidecar track); burnt-in subtitles are out of scope (deferred, noted below).
- [ ] Tests: `.srt` timing and escaping from a fixture plan; schema validation of `PublishCopy`; vitest for modal pre-fill and edit round-trip; routing-config integrity covers the new op.

## Notes

- A-009's v1 tier (per-scene title overlays, user-editable transcript, speech-to-text) stays out; MVP-lite is one structured LLM call plus deterministic `.srt` assembly, which is what made A-009 "small" in the first place.
- Caption cue text should come from the Stage 3 captions already paid for, not a fresh look at the frames — zero new vision calls.
- Burnt-in subtitles would require a Stage 7 `subtitles=` filter and a re-render; deferred until a platform without caption tracks (Instagram) proves to need them.
