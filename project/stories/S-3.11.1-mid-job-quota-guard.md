## Description

As a user who set a daily spend cap, I want a job to stop at the cap instead of discovering hours later that it ran past it or died on an exhausted provider balance. Today the cap is checked once, before the job starts, from a rough input-size estimate (`pipeline/runner.py:178`, the only `check_quota` caller); the `quota.py:6` docstring claims a "pre-job and per-stage check" that does not exist; `llm_clients/router.py:661-669` only records spend after each call; refinement (Stage 9 via `api/snapshots.py`) and title-card image generation run with no pre-flight at all; nothing simulates provider credit exhaustion, which is exactly how the 2026-06-17 cold run died after 2h55m; and the quota day boundary uses local `date.today()` (`quota.py:44,112,123`) while telemetry (`telemetry.py:34`) and YouTube's quota reset are UTC, so a job spanning local midnight sees its cap reset mid-run. Anthropic is ~99 % of spend and the per-provider caps have never been exercised at runner level. Restart plan §5 Phase 2 item 5.

## Acceptance criteria

- [ ] The router runs a pre-flight before every paid dispatch — `check_quota` against the total and the route's provider with the route's rate-card estimate — and a denial raises a classified `QuotaExceededMidJob` that `jobs/runner_glue._classify_failure` maps to a readable reason; the job ends in a terminal failed state with the partial snapshot artifacts kept
- [ ] Refinement (Stage 9) and title-card image generation go through the same pre-flight; refinement's check is sized by whether a re-judge is needed
- [ ] A credit-exhaustion simulation test makes a fake provider return its insufficient-credit error mid-Stage-3: the job fails fast with the readable reason, spend to that point is recorded, no retry storm (the 2026-06-17 failure shape)
- [ ] The per-provider cap is tested at runner level (today only the total cap is); Settings shows the caps actually enforced and which provider tripped
- [ ] The quota day boundary is UTC, matching telemetry and YouTube, documented in an ADR-0015 amendment and in the Settings copy; a test covers a job spanning local midnight
