## Description

As a user who shares trip videos as Instagram Reels, I want Approve & publish to offer Instagram alongside YouTube so the approved render reaches my account without a manual upload. Delivered 2026-05-11 in PR #34 (commit 4a44c51) as `backend/impact_crater/connectors/instagram.py`, a month before this story was backfilled — with the honest caveats: credentials are env vars (a long-lived user token, no in-app Facebook Login), publish defaults to dry-run (`IC_PUBLISH_DRY_RUN=1`), and no Instagram post, dry-run or live, has ever executed (the audit table is empty).

What shipped: the Meta Graph API Reels flow — `POST /{ig_user_id}/media` creates a container referencing the video URL + caption, `GET /{container_id}` is polled until `status_code=FINISHED`, `POST /{ig_user_id}/media_publish` publishes it, and the permalink is fetched for the audit row. The Graph API cannot take video bytes inline: real posting requires a publicly fetchable HTTPS URL for the MP4 via `IC_PUBLIC_BASE_URL` (e.g. an ngrok tunnel in front of `/api/snapshots/{id}/render.mp4`); without it the connector raises a `ConnectorAuthError` pointing at the env var, and dry-run validates without building the URL. Posting needs an Instagram Business or Creator account linked to a Facebook Page; Reels are always public, so `private` / `unlisted` are rejected with a `ConnectorValidationError` rather than mis-recorded in the audit log.

## Notes

- Dry-run: `connectors/dry_run.py::is_dry_run_enabled()` reads `IC_PUBLISH_DRY_RUN` (default `"1"`); `get_connector()` wraps every connector unconditionally, so a dry-run publish runs `validate_artifact` and returns a synthetic `external_id="dry-run-…"`; the audit row's platform is `"instagram (dry-run)"` (`api/publish.py:194`).
- Test coverage is stub-transport only: the HTTP request shape (multipart / query encoding against graph.facebook.com) has never been exercised, not even by dry-run — a mocked-HTTP test is plan Phase 2 item 13.
