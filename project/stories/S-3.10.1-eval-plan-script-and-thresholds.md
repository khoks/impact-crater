## Description

As the owner deciding whether a Stage 4–7 change made the videos better or worse, I want a $0, deterministic script that computes quality metrics from `plan.json` / `diagnostics.json` / `cast.json` on frozen fixtures, so every heuristic or prompt change carries before/after numbers instead of a feeling. The ad-hoc June probe, now kept as `docs/design/eval_headless_2026-06.py`, is the ancestor (its design artefacts were promoted to `docs/design/` by S-2.13.6); this story promotes the idea into `scripts/eval_plan.py`. Metrics: motion (video) share, chronology back-steps, named-destination coverage (every brief-named destination present or honestly flagged), per-viewpoint cap, consecutive same-combo runs, people/landscape balance, cast coverage, safety-floor leaks. Fixtures: the SW-US snapshot `b4b73c7b1fe044b7` (present under `projects/project-aa425a73c540/snapshots/` on 2026-10-24) and a Zion snapshot. Runs as `pytest -m eval` — `pyproject.toml` declares only the `integration` marker today.

## Acceptance criteria

- [ ] `scripts/eval_plan.py <snapshot_dir | plan.json>` prints and writes `eval.json` with all eight metrics; deterministic (same input → identical output), no network, no API key, no media files needed
- [ ] Frozen fixtures committed under `tests/fixtures/eval/` as JSON only (plan / diagnostics / cast — no media): SW-US `b4b73c7b1fe044b7` and one Zion snapshot; `tests/eval/test_eval_plan.py` under a new `eval` marker asserts each metric against thresholds (provisional until D-058 is written, then tightened to it)
- [ ] `--compare before.json after.json` prints a per-metric delta table and exits non-zero on a regression beyond tolerance; usage documented in `docs/dev/`
- [ ] `pytest -m eval` runs in CI (S-3.11.2) at $0, and the PR template asks for the eval delta on any Stage 4/5/6/7 or prompt change
