## Description

As a user refining a video, I want a request like "look again at the Narrows shots — is anyone smiling?" to make the AI re-examine those specific photos with the new question before re-planning, so refinement can use information that the first analysis did not extract. The shipped refinement (E-2.12, D-056) is one structured `RefinementOutcome` call over the analysis already on disk; its five levers (pacing directive, destination / media reservations, brief addendum, title-card patch, explanation) never re-run Stage 3. The `reanalyze_media` tool that E-2.12's design named (and that S-2.12.3's acceptance list still carries as an open box deferred here) would add a sixth lever: a set of media refs plus extra prompt variables for `extract_metadata_image`, cached under a distinct key so the base metadata stays valid, feeding the re-judge.

## Acceptance criteria

- [ ] `RefinementOutcome` gains a `reanalyze_refs` lever (refs + question); the planner prompt describes when to use it
- [ ] Stage 3 can be re-run for those refs with the extra question, cached separately from the base metadata (content hash + question hash)
- [ ] The re-judge sees the new metadata; a request that depends on it changes the plan on a fixture
- [ ] Cost is pre-checked (the mid-job quota guard, S-3.11.1) and shown in the child snapshot's cost summary once S-3.5.5 writes one
