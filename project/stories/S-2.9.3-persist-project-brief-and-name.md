## Description

As a user with multiple projects, I want each project row to carry the name and brief I submitted, so the dashboard list (S-2.9.2) and any later profile/derivation work can show meaningful labels instead of `project-3d1ac44eba32`.

Gap confirmed 2026-06-11: all 9 project rows in the live DB have empty `name`/`brief` — `stage6_plan._persist` auto-creates rows with `name = project_id`, and the submit path never writes the user's `project_name`/`brief` (they only live on the in-memory JobSnapshot).

## Acceptance criteria

- [ ] `POST /api/jobs/submit` (and `/render`, `/headless` where a project row is created) upserts name + brief onto the projects row
- [ ] Existing rows update when a job re-runs with the same project_id and a different brief
- [ ] S-2.9.2's list shows the persisted name/brief
