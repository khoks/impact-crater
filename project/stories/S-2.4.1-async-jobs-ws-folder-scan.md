## Description

The M2 `POST /api/jobs/render` is synchronous (blocks 22s+). The M3 UI needs async submission + a progress stream. Add:

- `POST /api/jobs/submit` accepts the same request shape as `/render` but returns immediately with `{job_id, project_id, snapshot_id, websocket_url}`. The pipeline runs as a background asyncio task.
- `GET /api/jobs/{job_id}` returns current state (`queued | running | succeeded | failed | cancelled`), per-stage progress, live cost rollup.
- `WS /api/ws/jobs/{job_id}` streams `JobProgressEvent` messages (stage advances, LLM call cost-delta, render-complete, terminal state).
- `GET /api/folder/scan?path=<dir>` recursively lists supported media files in `dir` (per ADR-0010 photo + video extensions). Local-first: backend has filesystem access. Returns `{paths, photo_count, video_count, total_bytes}`.
- `GET /api/effort-levels` returns `[{id: "L1"|"L2"|"L3", photo_cap, video_cap, estimated_cost_usd_low, estimated_cost_usd_high, fits_today_budget: bool}]`.
- `POST /api/jobs/cost-preview` accepts `{media_paths, target_duration, level?}` and returns the estimated cost broken down by tier + provider, plus the user's remaining daily budget.

The synchronous `POST /api/jobs/render` and `POST /api/jobs/headless` stay for backward-compat with the integration tests.
