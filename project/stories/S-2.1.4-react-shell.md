## Description

Stand up the React app skeleton: Vite for build/dev, TypeScript strict mode, Tailwind for styling, react-router-dom for client-side routing (Setup ↔ Dashboard), Zustand for global state (current setup-complete flag, current project later). On first paint, the app calls `/api/setup/status` and routes to `/setup` or `/dashboard` accordingly. Vitest placeholder configured + green.

## Acceptance criteria

- [x] `frontend/package.json` with the M0 frontend deps + scripts (dev / build / preview / test / test:watch / typecheck)
- [x] `tsconfig.json` + `tsconfig.app.json` (strict mode for src) + `tsconfig.node.json` (vite/vitest configs)
- [x] `vite.config.ts` with React plugin + `/api` proxy to FastAPI in dev (port 8765 default; overridable via `IC_API_TARGET`)
- [x] Tailwind configured (`tailwind.config.js` + `postcss.config.js` + `src/styles/globals.css`)
- [x] `App.tsx` calls `/api/setup/status` on first paint; routes between `/setup` and `/dashboard` based on the response; shows "Loading…" until the call resolves; navigates to `/setup` when incomplete and `/dashboard` when complete; SPA fallback for unknown routes
- [x] Zustand store skeleton (`setupStore.ts` with `status: "unknown" | "incomplete" | "complete"`)
- [x] `vitest.config.ts` + `src/test-setup.ts` (jest-dom + cleanup) + `src/__tests__/App.test.tsx` covering the loading → /setup and loading → /dashboard branches with mocked fetch
