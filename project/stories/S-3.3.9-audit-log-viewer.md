## Description

As the owner, I want to see every publish attempt the app has made — dry-runs and live posts — in one place, with which video file each one approved, so that I can answer "what did the app post, where, when, and was it real?" without opening SQLite or `audit.jsonl`. Restart plan Phase 1 item 8 (`docs/roadmap/LANDSCAPE-AND-PLAN-2026-10-24.md` §5). Today the only reader is `GET /api/projects/{id}/audit` (one project at a time, no UI). Since S-3.3.8 (2026-11-03) every row carries `render_content_hash`, so a row can be tied to its file.

## Acceptance criteria

- [ ] An app page (Dashboard link or Settings section) lists audit rows across all projects, newest first: time, project, snapshot, platform with a clear dry-run / live marker, visibility, external URL (link for live posts), response code, approval token and a short render hash
- [ ] A row links to its snapshot's Inspect view, and shows whether the render file on disk still matches the recorded hash
- [ ] The backend serves the cross-project list through one paginated endpoint (token-protected like the rest of `/api`, ADR-0022)
- [ ] Tests: endpoint ordering and pagination; vitest for the dry-run / live marker and the hash-mismatch state
