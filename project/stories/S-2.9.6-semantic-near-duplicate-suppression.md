## Description

As a viewer, I never want to see two retakes of the same pose in one video. pHash (Hamming ≤ 5) only catches near-identical pixels; a retake from a slightly different angle survives today. Stage 2 already computes and caches an embedding per asset that nothing consumes — Stage 4 should cluster by embedding similarity (cosine, time-windowed), keep the best shot per cluster by the existing combined score, and drop the rest with filter-log reasons. Full design in A-017.

## Acceptance criteria

- [ ] Embedding-similarity clustering pass in Stage 4 (threshold ~0.92, ±2min time window), layered after pHash
- [ ] Best-of-cluster kept by combined score; `burst_best_of: N` annotation reaches Stage 5's prompt
- [ ] Dropped retakes appear in filter_log with reason `semantic_duplicate` (cost-transparency UI can count them)
- [ ] Calibrated against the Zion subset (contains true retake pairs: e.g. PXL_223736116/223737985, PXL_224017934/224020089)
- [ ] Dedup aggressiveness exposed as a PreFilterOverrides knob
