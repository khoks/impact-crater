## Description

As the owner approving a publish, I want every word and default in the Approve & publish panel to describe what will really happen, so that "approve" never surprises me. Restart plan Phase 1 item 5 (`docs/roadmap/LANDSCAPE-AND-PLAN-2026-10-24.md` §5), sharpened by the first dry-runs on 2026-11-03 (S-2.9.21), which showed the panel contradicting the connectors in several places.

## Acceptance criteria

- [ ] The caption under the buttons is derived from live connector status and the dry-run flag (today it always reads "Approve uploads this MP4 to your connected YouTube account.", even in dry-run with nothing connected) — shared with S-3.3.5's caption criterion
- [ ] The visibility selector offers only what the chosen platform supports: Instagram public only (the panel says "visibility selector is ignored" while the server rejects `private`), Facebook public / unlisted-as-draft (the server rejects `private`), YouTube all three; the first-run default is `private`
- [ ] Title and description default from the title card text and the brief, not `Story Video — ` + the first 8 characters of the project ID (which renders as "Story Video — project-")
- [ ] The dry-run hint says what dry-run checks per platform: YouTube validates without credentials; Instagram and Facebook refuse until their credentials are set, so a dry-run there is a credential check, not only a request-shape check
- [ ] Setup hints link to a Settings page or the published docs, not repo paths like `docs/connectors/youtube-setup.md`
- [ ] The audit row records the render that was approved (`render_content_hash` is empty today) so the audit-log viewer (plan item 8) can tie a post to its file
- [ ] Dry-run is a Settings toggle that takes effect without a restart (plan item 5); "connected" never implies "live"
