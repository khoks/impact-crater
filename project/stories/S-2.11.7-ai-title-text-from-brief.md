## Description

As a user who opts into the AI title/splash card, I want the auto-derived title (when I don't type my own) to be a short, clean, human phrase that captures the video's spirit — not a mechanical slice of my brief that carries my typos. The old `_derive_title` took the first clause, dropped filler words, and title-cased the first 5 words, so a brief like *"A highlight video of our early-April trip through zion, bryce, horseshow bend, grand canyon, and las vegas"* produced **"Early-April Through Zion Bryce Horseshow"** — awkward, and it kept the "horseshow" typo.

## Acceptance criteria

- [x] When `title_text` is not supplied, the card title comes from a cheap Tier-S LLM call that reads the brief + year and returns a short (2–5 word) evocative title, fixing obvious place-name typos.
- [x] Fully fail-soft: any router error (missing key, quota-denied, non-JSON, empty output) drops to the existing `_derive_title` heuristic, then to "Our Trip" — the render is never blocked.
- [x] An explicit user-supplied `title_text` short-circuits the LLM call (no cost when not needed).
- [x] Respects the existing shrink-to-fit title rendering (`_fit_font`) — no layout regression for long titles.
- [x] Unit tests cover the LLM-title path, each fallback branch, and output sanitization.

## Notes

- New router op `generate_title_text` (Tier-S, `google` / `gemini-2.5-flash`, `max_tokens: 64`, `temperature: 0.5`), reusing the existing structured-text primitive (`client.parse_user_brief` → JSON `{title}`) rather than adding a new `LLMClient` protocol method. Cached on `sha256(brief, year)`; empty outputs are not cached so a transient blank re-tries next run.
- New prompt `prompts/generate_title_text/google_gemini-2.5-flash.jinja2`.
- Stage wiring: `stage6_title_card._title_from_brief` (LLM → `_clean_title` → heuristic) + `_clean_title` (strips wrapping quotes / edge punctuation). `_derive_title` is retained as the fail-soft fallback.
- Follow-up to S-2.11.5. Decision recorded as **D-055**. **Future enrichment:** once named-destination parsing / GPS reverse-geocoding lands (S-2.10.5), pass explicit top-locations into the prompt instead of relying on the brief text — tracked as **A-026**.
