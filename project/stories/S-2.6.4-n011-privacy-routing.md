## Description

Per ADR-0016. Each operation gets a `privacy_class` (`face_data` / `visual_only` / `derived_metadata` / `text_only`); each provider gets `eligibility_for_class`. The router consults the project's privacy posture before dispatching: when blur-faces=ON, `face_data` ops route to providers eligible for `face_data` only.

At MVP no local provider exists, so face_data + blur_faces=ON means **degraded mode** — Stage 3 returns recognized_persons=[] without sending the photo. Stage 5 falls back to the no-person-specific-motifs prompt branch.

The schema lands now so v1's local-LLM swap is a config flip, not a code change.

## Acceptance criteria

- [x] `config/llm-routing.yaml` extended: `privacy_class` per operation, `providers.{anthropic,google}.eligibility_for_class` lists
- [x] `LLMRouter` consults privacy posture before dispatch; raises `PrivacyDegradedError` (or returns sentinel) when no eligible provider
- [x] Stage 3 catches degraded-extraction and returns `recognized_persons=[]` + a flag the runner can surface to the UI
- [x] `tests/test_router_privacy.py` — eligibility-matching + degraded-mode behavior
