## Description

As the owner merging my own PRs, I want every PR checked by CI on Linux as well as Windows, so that a merge can no longer land a red suite and the ADR-0004 `--admin` bypass can be retired for `--auto` with real status checks behind it. Today `.github/workflows/` holds only `pages.yml`; the backend suite (483 collected / 476 pass / 7 integration-gated per the 2026-10-24 audit; 58 `test_*.py` files under `tests/` and `tests/integration/` by count) has only ever run on the owner's Windows machine with the main-repo venv; the 10 vitest files / 38 tests and `tsc` likewise; coverage is configured without a threshold; nothing proves the suite passes on Linux (mediapipe wheel, `scenedetect[opencv-headless]`, apt ffmpeg); and the GitHub Pages deploy installs a floating `mkdocs-material` with no build check. Restart plan §5 Phase 1 item 3; landscape §4.4 recommended test addition 2.

## Acceptance criteria

- [ ] `.github/workflows/ci.yml` on push and PR to master: ruff, mypy and `pytest` (non-integration, ffmpeg installed, run from the repo root per `testpaths`) on `ubuntu-latest` and `windows-latest` with Python 3.12; `npm ci && npm run typecheck && npm test && npm run build` in `frontend/`; `mkdocs build --strict` with `mkdocs-material` pinned; coverage printed with a floor set to today's measured value
- [ ] The Linux job is green — the first proof the suite passes anywhere but Windows; any Linux-only failures fixed or skipped with a dated reason
- [ ] Branch protection on master requires the CI checks; the `knowledge-curator` and `work-tracker` skills, CLAUDE.md and `project/README.md` switch `gh pr merge --squash --delete-branch --admin` → `--auto`; recorded as a D-NNN plus an ADR-0004 amendment (its "CI gate" revisit trigger fired)
- [ ] Dependabot PRs (config from S-2.13.5) run the same workflow
