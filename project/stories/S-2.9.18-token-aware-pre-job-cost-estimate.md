## Description

D-048 fixed the *actual* per-call cost meter (real token usage × rate cards).
But the **pre-job estimate** — the cost-preview shown before submit and the
quota pre-flight check (`_estimate_cost_per_provider`) — is a *separate*
estimator that still uses coarse per-tier/per-asset assumptions. On the 1,663-
asset job it quoted $14–22 while the real cost was ~$19+ (and would have been
mis-gauged under the old meter). Make the pre-job estimate consistent with the
corrected costing so the upfront number the user approves matches reality, and
so the quota gate is honest.

## Acceptance criteria

- [ ] Pre-job estimate uses representative per-op token counts (or calibrated per-asset figures) consistent with `rate_cards`, not the old ballpark.
- [ ] Account for video scene-splitting (the estimate should reflect post-split shot count, not raw file count — same gap as the Stage-2 progress fix).
- [ ] Estimate vs actual on a real job lands within a sensible band; document the assumptions.
