## Description

As a user returning to the app after a job (or a server restart), I want the dashboard to list my projects and their rendered snapshots so I can re-watch, approve, or publish a result without digging through `~/.impact-crater/projects/` on disk.

Gap confirmed 2026-06-11: `GET /api/projects` returns a hardcoded `[]` ("M0 placeholder — project rows arrive in M3") and `Dashboard.tsx` hardcodes "No projects yet." even though 9+ project rows and snapshots exist in SQLite. Jobs live only in the in-memory registry, so after a restart there is **no UI path back to a finished render** — a direct usability blocker for the D-014 validation flow (run a 2–5 hour job, come back, approve, publish).

## Acceptance criteria

- [ ] `GET /api/projects` returns real rows (id, name, brief, created_at, snapshot count, latest render status/path)
- [ ] Dashboard lists projects with their latest snapshot state; clicking through reaches the preview/approve surface for a finished render
- [ ] Works after server restart (no dependency on the in-memory job registry)
- [ ] Empty state preserved for genuinely-fresh installs
