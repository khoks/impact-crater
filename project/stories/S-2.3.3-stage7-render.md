## Description

Per ADR-0010 + ADR-0011 Stage 7 + ADR-0012 (standard mode) — ffmpeg subprocess execution from a `RenderPlan`. H.264 / yuv420p / AAC; 1080p / 30fps for 16:9 (D-007 YouTube-friendly defaults). Two-pass `loudnorm` at -16 LUFS / true-peak -1.5 dB / LRA 11. Background music mixed under the entire video; 1.5s fade-in at start; fade-out at target_duration when music is longer than target.

Music-video mode (beat-snap) is M4 — out of scope here.

## Acceptance criteria

- [x] `backend/impact_crater/pipeline/stage7_render.py` — `render_plan(plan, *, correlation_id, pool) → RenderResult`
- [x] Photo clips → `ffmpeg -loop 1 -t <dur>` per clip with explicit aspect-action filter chain (smart_crop = scale-then-center-crop; letterbox / pad = scale + black pad). yuv420p TV range forced via `-color_range tv` so JPEG sources don't bleed full-range yuvj420p through.
- [x] Video clips → `ffmpeg -ss <start> -t <dur>` trim
- [x] Concat demuxer joins normalized segments
- [x] Two-pass loudnorm: pass 1 prints measurement JSON to stderr (parsed via regex), pass 2 applies with measured I/LRA/TP/thresh/offset; afade in/out scheduled at 1.5s each by default; atrim to target_duration
- [x] Subprocess registered with the worker pool via `register_subprocess` hook → `cancel()` SIGTERMs in-flight ffmpegs
- [x] Output at `snapshots/{snapshot_id}/render.mp4`; `RenderResult` carries duration_ms / output_bytes / ffmpeg_exit_code / status; snapshot DB row transitions pending → in_progress → success/failure
- [x] RenderEvent telemetry emitted on both success and failure with correlation_id + ffmpeg_exit_code + stderr_excerpt
- [x] `tests/test_stage7_render.py` (5 tests, gated on `has_ffmpeg()`) — 2-photo no-music render, 1-photo + WAV with full audio normalize/fade/trim, snapshot status transitions, render telemetry, failure path
