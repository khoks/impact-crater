## Description

Post-setup-wizard the user needs a Settings surface to edit API keys + spend caps + see the privacy posture (full privacy panel lands in M5). Per ADR-0015 §"UI surfaces" point 4.

## Acceptance criteria

- [ ] `frontend/src/routes/Settings.tsx` — edit Anthropic key / Google key / total cap / per-provider caps
- [ ] Backend: `GET /api/settings/snapshot` returns `{has_anthropic_key, has_google_key, spend_cap_total_usd, spend_cap_anthropic_usd, spend_cap_google_usd}` (booleans for keys; never returns plaintext) — also returns today's spend snapshot
- [ ] Backend: `POST /api/settings/update` accepts the same fields (keys optional — empty string = leave unchanged)
- [ ] Privacy panel placeholder: shows the M5 toggles greyed out with "Editable in M5" tooltips
- [ ] Dashboard navbar links to `/settings`
- [ ] `frontend/src/__tests__/Settings.test.tsx` — snapshot fetch, update flow, key-test affordance
