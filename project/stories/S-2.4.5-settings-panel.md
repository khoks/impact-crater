## Description

Post-setup-wizard the user needs a Settings surface to edit API keys + spend caps + see the privacy posture (full privacy panel lands in M5). Per ADR-0015 §"UI surfaces" point 4.

## Acceptance criteria

- [x] `frontend/src/routes/Settings.tsx` — Anthropic key + Google key (with `set` badge when present) + total/anthropic/google caps + privacy-panel placeholder + Save button
- [x] Backend: `GET /api/settings/snapshot` (S-2.4.1) returns booleans for keys + cap floats + today's spend
- [x] Backend: `POST /api/settings/update` (S-2.4.1) accepts partial updates; null/empty fields ignored
- [x] Privacy panel placeholder lists the 3 toggles with "Editable in M5 (E-2.6 person library + privacy panel)" copy
- [x] Dashboard navbar links to `/settings` (added in S-2.4.2)
- [x] `frontend/src/__tests__/Settings.test.tsx` (4 tests) — snapshot loads + 'set' badges; empty-state placeholders; partial-update payload (rotated key + bumped cap, untouched key sent as null); 422 error surfaced
