## Description

As a user with a long trip, I want a snappy edit that covers everywhere I went — short 2–3s clips, every distinct location/time represented, no single viewpoint hogging the reel, no 5–8s held photos and no jerky <2s video flashes.

## Acceptance criteria

- [x] Stage 6 hard-caps each photo at 1–3s and never stretches photos to fill an under-populated target (the 8000ms opener is gone); videos clamp to [2s, natural].
- [x] Stage 4 makes a video scene <2s ineligible (`video_too_short`).
- [x] The judge prompt states the per-clip duration model (2–3s photo / 2s+ video) and the resulting clip-count (~target/3..target/2), so it selects ~40–60 clips for 120s and uses them to cover EVERY distinct location AND time-of-day; caps any single viewpoint at ~2–3.
- [x] Judge `max_tokens` raised (4096→8192) for the larger clip list.
- [x] Tests: duration-cap band, min-video eligibility, music-video beat-snap preserved (legacy linear scale). Full suite 406 pass.
- [ ] Chrome re-render verify: ~40–60 clips, no photo >3s, no video <2s, broader GPS coverage, no viewpoint >~3. (Re-run in flight.)

## Notes

The linchpin was the duration cap: the old `_scale_to_target` stretched photos to fill the target when the judge under-populated it (5–8s photos). Capping per-clip forces the judge to pick more, shorter clips — which also improves coverage for free. Music-video mode keeps the legacy linear scale (beats drive pacing, not a per-clip band). Addresses feedback #1,2,3,4,6. Committed as af83d0c.
