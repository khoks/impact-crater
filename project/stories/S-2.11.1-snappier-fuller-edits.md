## Description

As a user with a long trip, I want a snappy edit that covers everywhere I went — short 2–3s clips, every distinct location/time represented, no single viewpoint hogging the reel, no 5–8s held photos and no jerky <2s video flashes.

## Acceptance criteria

- [x] Stage 6 hard-caps each photo at 1–3s and never stretches photos to fill an under-populated target (the 8000ms opener is gone); videos clamp to [2s, natural].
- [x] Stage 4 makes a video scene <2s ineligible (`video_too_short`).
- [x] The judge prompt states the per-clip duration model (2–3s photo / 2s+ video) and the resulting clip-count (~target/3..target/2), so it selects ~40–60 clips for 120s and uses them to cover EVERY distinct location AND time-of-day; caps any single viewpoint at ~2–3.
- [x] Judge `max_tokens` raised (4096→8192) for the larger clip list.
- [x] Per-viewpoint cap is DETERMINISTIC (Stage 6, ≤3 clips per ~1km GPS cell) — the soft prompt cap alone was overridden by the judge for iconic spots.
- [x] Tests: duration-cap band, min-video eligibility, per-viewpoint cap, music-video beat-snap preserved. Full suite 408 pass.
- [x] Verified on the real SW-US-trip media (cached reconstruction → real Opus judge): 37 clips (was 17), photo max 2500ms (was 8000), 0 photos>3s, 0 videos<2s, 14 distinct GPS locations (was ~7), max 3 clips/viewpoint (Horseshoe Bend 6→3).

## Notes

The linchpin was the duration cap: the old `_scale_to_target` stretched photos to fill the target when the judge under-populated it (5–8s photos). Capping per-clip forces the judge to pick more, shorter clips — which also improves coverage for free. Music-video mode keeps the legacy linear scale (beats drive pacing, not a per-clip band). Addresses feedback #1,2,3,4,6. Committed af83d0c + 8eb0a4b.

Known trade-off / refinement (T-2.11.1.6, follow-up): the deterministic per-viewpoint cap DROPS the judge's excess clips without refilling, so a heavily-clustered selection ends ~20% under the target (the verified run came to 96s for a 120s target). The cleaner fix is to cap per-viewpoint at the CANDIDATE level (Stage 4) so the judge fills the full target from breadth rather than over-picking then being trimmed. Shipped the Stage-6 cap first because it's the hard guarantee for #2; the candidate-level refill is a tuning follow-up.
