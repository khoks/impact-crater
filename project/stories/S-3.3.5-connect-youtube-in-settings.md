## Description

As a self-hosting user, I want to click **Connect YouTube** in Settings, approve once in my browser, and see "Connected as <channel>" — instead of running a mint script and exporting three shell variables — so the first real publish needs no terminal work and the Approve button's "your connected YouTube account" copy becomes true.

Today `backend/impact_crater/connectors/youtube.py:5-16` has two credential paths: the env-var path (`IC_YOUTUBE_CLIENT_ID` / `IC_YOUTUBE_CLIENT_SECRET` / `IC_YOUTUBE_REFRESH_TOKEN`, obtained via the one-time consent flow in `docs/connectors/youtube-setup.md`) takes precedence, and the DB-backed `connector_credentials` table (ADR-0013; Fernet-encrypted via `backend/impact_crater/crypto.py::encrypt/decrypt`; load / upsert / delete helpers at `youtube.py:236-297`) is read but never written because the OAuth init / callback was never finished. `GET /api/connectors/youtube/status` reads `user_handle` from that table (`api/publish.py:243`), `frontend/src/routes/Settings.tsx` has no connector section, and `JobPreview.tsx:207` promises a connected account while nothing is connected and publish defaults to dry-run. Plan Phase 1 item 6.

## Acceptance criteria

- [ ] `GET /api/connectors/youtube/oauth/start` builds the Google consent URL for a Desktop OAuth client with a loopback redirect (`http://127.0.0.1:<server port>/api/connectors/youtube/oauth/callback`), PKCE and a one-shot `state`; the callback exchanges the code, fetches the channel handle, and upserts Fernet-encrypted access + refresh tokens and expiry into `connector_credentials` (`connector_name="youtube"`) through the existing helpers.
- [ ] Settings gains a Connectors card: YouTube "Not connected" → **Connect** → "Connected as <handle> · token refreshed <date> · expires <date>" with **Disconnect** (deletes the row and revokes the token at Google).
- [ ] Connector status (`/api/connectors/youtube/status` and whatever the platform picker calls) reports connected from DB-or-env and says which source; the Approve caption in `JobPreview.tsx` and the default visibility derive from it — no "connected account" copy when nothing is connected.
- [ ] Publish uses DB credentials when present, env vars only as a fallback (precedence documented in `docs/connectors/youtube-setup.md`); expired access tokens are refreshed; a revoked or expired refresh token maps to 401 with a "Reconnect in Settings" action instead of a 502.
- [ ] Slip fallback if the loopback flow misses Phase 1: a Settings form for client id / secret / refresh token that writes the same table Fernet-encrypted and never echoes the plaintext back.
- [ ] Tests: callback upsert, status (DB / env / none), disconnect, and refresh-failure mapping against a stub token endpoint; no plaintext token appears in logs or API responses.
- [ ] Phase 1 exit evidence appended to this activity log: connector status "connected" via the DB path with every `IC_YOUTUBE_*` env var unset, followed by a dry-run publish that writes an audit row.

## Dependencies

- Blocked by: S-3.11.3 (local API hardening) before any non-loopback exposure — the callback and the Settings mutation routes stay on 127.0.0.1 and a non-loopback `--host` must refuse without an explicit `--allow-remote`; no route or WebSocket checks authentication or origin today.
- Blocked by: the OAuth publishing-status decision (plan Phase 1 item 3c): a Google OAuth client in **Testing** status issues refresh tokens that expire after 7 days, while **Production** means verification (or an unverified-app warning screen) for the sensitive `youtube.upload` scope. Both the env-var token and the stored token break weekly until this is decided; the status card must surface expiry and last refresh either way.
- Prerequisite (owner): `docs/connectors/youtube-setup.md` Step 1 — a Google Cloud project with the **YouTube Data API v3** enabled and a **Desktop app** OAuth client; its client id / secret feed the loopback flow.
- Blocks: plan Phase 1 item 4 (first publish through the DB path); S-3.3.4's Settings connect flow and the Phase 4 Meta Connect reuse this pattern; the audit-log viewer (Phase 1 item 8) sits beside the Connectors card.

## Notes

- The ADR-0013 amendment pending from the Phase 0 ADR truth bundle records the env-var + dry-run model layered beside this dormant OAuth / Fernet path; this story is what makes the original ADR-0013 design real.
- The Fernet key lives at `~/.impact-crater/db/.fernet-key` beside the SQLite file; the "restrictive permissions" claim in `crypto.py` is a no-op on Windows NTFS, and losing the key bricks every stored token — the key-management section (backup / restore, key-loss recovery) is owed by the same ADR bundle and should link here.
- YouTube Data API quota: 10,000 units / day, 1,600 per upload (~6 uploads / day, UTC reset) — surface it on the status card as a budget input for Phases 4 and 6.
- Keep the dry-run toggle visible next to the card (plan Phase 1 item 5 makes it a Settings toggle instead of an env var) so "connected" never implies "live".
