## Description

As a user, sometimes a place is important enough that we took many photos there with the same backdrop but different people/poses/angles within a short window. I want the option of a rapid **burst-montage** — ~0.5s photos squished into a 2–4s sequence — to capture all of them at once, used occasionally (not every cluster), especially when there's a lot of same-backdrop media within ~30 minutes.

## Acceptance criteria

- [x] Stage 4/5 can mark a tight cluster (same location + ≤30 min window + ≥~6 near-same-backdrop photos) as a candidate burst-montage group. — verified by backend/impact_crater/pipeline/stage4_prefilter.py:1006-1040 (`_detect_montage_groups`: GPS photos in one ~1km cell, ≤1800 s window, pHash Hamming ≤14, ≥6 members — defaults :120-122; called :250-257 before the viewpoint cap; surviving groups re-filtered :320-325) and tests/test_stage4_prefilter.py::test_montage_group_detected_for_dense_same_backdrop_burst (:506) + ::test_no_montage_without_gps_or_too_few (:527); PR #67 (2026-10-24)
- [x] Stage 6 emits a `burst_montage` clip group: N photos at ~0.4–0.6s each (total 2–4s), one entry in the timeline. — verified by backend/impact_crater/pipeline/stage6_plan.py:330-375 (`_collapse_montage_groups` → one `burst_montage` RenderClip via `_montage_clip`; members 400–600 ms each, 2–4 s total, ≤8 members — constants :50-54) and tests/test_stage6_plan.py::test_compile_collapses_montage_group (:113); PR #67 (2026-10-24)
- [x] Stage 7 renders the sequence (fast cuts, optional subtle zoom) as one segment. — verified by backend/impact_crater/pipeline/stage7_render.py:230-231 (dispatch) and :295-335 (`_prerender_montage`: per-member micro-segments concatenated stream-copy into one timeline segment; hard cuts, no zoom — the zoom was optional) plus the 1080p mixed-aspect render smoke run recorded in the activity log 2026-06-30 (PR #67); no unit test in tests/test_stage7_render.py (2026-10-24)
- [ ] Used sparingly — at most a couple per video, gated on cluster density; the judge decides when it serves the story. — superseded by deterministic Stage-4 density gating (≥6 photos / ≤1800 s / pHash ≤14 per GPS cell — stage4_prefilter.py:120-122,1006; `montage_enabled` and the thresholds are reachable only via `PreFilterOverrides`, which no API endpoint exposes per the restart audit): there is no per-video cap on montage count and the Stage 5 judge is not consulted (backend/impact_crater/pipeline/stage5_judge.py has no montage awareness) (2026-10-24)

## Notes

Design: extends the clip model with a montage group (a RenderClip variant carrying a list of member photos + per-member micro-durations), Stage 6 builds it from a Stage-4-tagged dense cluster, Stage 7 renders the rapid sequence. Interacts with S-2.11.1's duration band (the band is per-normal-clip; montage members are intentionally sub-band). Feedback #5.
