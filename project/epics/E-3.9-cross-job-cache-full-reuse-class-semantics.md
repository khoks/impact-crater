## Goal

Extend the cache from MVP-lite (universal + model-versioned) to the full N-007 schema (task-context-specific + time-bounded classes) with a hit-rate dashboard — and, before any of that, make the caches bounded and deletable: scene frames and thumbnails are written per project today, so re-ingesting the same trip duplicates ~13 GB in a 92 GB tree, telemetry has no rotation, the LLM cache has no GC, and nothing can delete a project's derived data (landscape §4.2, A-027). The restart plan puts the disk/telemetry hygiene and the delete path in Phase 2 (they must precede the Phase 3 full-scale runs), the two-phase pre-filter in Phase 3 (it halves Tier-M spend on large jobs), and the reuse classes + hit-rate dashboard in Phase 4, starting with one concrete GC rule: purge payloads for the model IDs retired by S-2.10.9.

## Scope

- S-3.9.3 — shared content-addressed scene/thumbnail cache + disk accounting + cleanup + telemetry rotation + LLM-cache GC (A-027; Phase 2 item 9)
- S-3.9.4 — delete project / forget media, tombstone telemetry, never delete published snapshots (Phase 2 item 9)
- S-2.9.15 — two-phase pre-filter: cheap Stage-2-only pass before rich-metadata extraction, ≥ 40 % Tier-M saving proven by kept-set overlap (Phase 3 item 3)
- S-3.9.1 — full N-007 reuse-class semantics + partial-hit handling (Phase 4)
- S-3.9.2 — cache hit-rate dashboard + perf smoke (Phase 4)

## Out of scope

- Durable job registry and orphaned-job handling (S-2.9.19 under E-2.9 — this epic only cleans their bytes); the one-off owner-approved purge of the 13 snapshot-less projects (Phase 1 item 2, done by hand before S-3.9.3 lands); hosted object storage (I-5).
