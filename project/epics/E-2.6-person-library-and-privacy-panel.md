## Status

**Closed at MVP scope** with two stories deferred to v1:

- **Shipped (M5):** S-2.6.1 (person library DB + CRUD API + reference-collage builder), S-2.6.3 (privacy pipeline: piexif EXIF strip + mediapipe face-blur with per-project cache), S-2.6.5 (frontend person library page + dashboard People link).
- **Deferred (v1):** S-2.6.2 (Stage 3 N-008 integration — sending the collage as a 2nd image input requires invasive LLMClient Protocol changes), S-2.6.4 (N-011 privacy-routing eligibility schema — only meaningful once ADR-0008's local-LLM destination exists).

The collage + library + privacy transforms are end-to-end usable today; v1's local-LLM work picks up the deferred stories without rework.

## Goal

Implement the **N-008 person-library + reference-collage face-recognition** mechanism end-to-end, plus the privacy panel UI that exposes the three project-level toggles (strip-EXIF / strip-GPS-only / blur-faces). Land the N-011 privacy-routing schema in the routing config + LLMRouter so v1's local-LLM ships the feature plug-and-play.

This is **M5**, the longest single milestone for UI iteration. The person library is **opt-in** at MVP — users can ship Story Videos without ever touching it.

## Scope

- SQLite schema extension for `persons` + `person_face_photos` tables per [ADR-0006](../../docs/architecture/ADR-0006-storage-layout.md) + [ADR-0010](../../docs/architecture/ADR-0010-media-pipeline-framework.md).
- React UI: person-library management page (list of persons + add-person form); face-photo cropper UI (drag-and-drop photo + crop a face region; or pick face crop from existing project media); per-person photo grid (5 default; 3-10 range).
- Reference-collage builder: tile labeled face crops into a single image cached at `~/.impact-crater/cache/face-library/{library_version_hash}.png`.
- Stage 3 rich-metadata extraction integration: when person library is non-empty, send the reference collage as a second image input to `extract_metadata_image` and parse `recognized_persons` from the structured-output schema.
- Confidence handling: ≥0.85 used directly downstream; 0.5–0.85 surfaced for user confirmation in metadata-review UI; <0.5 discarded.
- Cache key extension: include `library_version_hash` in `extract_metadata_image` cache key per [ADR-0007](../../docs/architecture/ADR-0007-remote-llm-abstraction.md).
- EXIF/GPS strip pipeline per [ADR-0010](../../docs/architecture/ADR-0010-media-pipeline-framework.md): `pyexiv2`-based byte-level strip; cached at `~/.impact-crater/projects/{project_id}/cache/stripped/{content_hash}.{ext}` keyed by strip mode.
- Face-blur pipeline per [ADR-0016](../../docs/architecture/ADR-0016-privacy-posture-defaults.md): one face-detection-only library (decision between `face-recognition` (dlib) and `mediapipe` finalized in this epic; recommend dlib's `face-recognition` for accuracy at the dependency cost); Gaussian blur on detected boxes; cached.
- React UI: privacy panel in Settings with three toggles + interaction matrix explainer + plain-English "what we send to LLM providers" surface.
- LLMRouter extension: per-operation `privacy_class` + per-provider `eligibility_for_class` per [ADR-0016](../../docs/architecture/ADR-0016-privacy-posture-defaults.md) (N-011). At MVP no local provider exists, so `face_data` ops still route to remote when blur-faces=OFF; when blur-faces=ON, ops route to local OR skip-with-degraded-fallback (the latter is what happens at MVP since no local provider exists yet).
- Stage 5 prompt template variants for the degraded-metadata case (recognized_persons empty; person-specific descriptors absent).
- Project Privacy Banner UI surface: when degraded mode is active, show the consequence to the user.

## Out of scope

## Acceptance criteria

- [ ] User can add a person via the UI; cropper UI lets them pick a face region from a photo
- [ ] User can add 5 face photos per person via either the cropper or direct upload
- [ ] Reference collage builds and caches; collage shows labeled face crops in a tiled layout
- [ ] Stage 3 metadata extraction returns `recognized_persons` populated for at least 3 real persons in real test photos with confidence ≥0.85
- [ ] Privacy panel exposes all three toggles; toggle interaction matrix matches ADR-0016
- [ ] Strip-EXIF + strip-GPS-only paths produce stripped variants in cache; original media untouched
- [ ] Face-blur path produces blurred-face variants when blur-faces=ON; cached per content_hash
- [ ] Routing config schema includes `privacy_class` per operation + `eligibility_for_class` per provider; LLMRouter consults privacy posture before routing
- [ ] When blur-faces=ON and no local provider available, `face_data` ops degrade gracefully (recognized_persons=[], people={count: best-effort, demographics: null}) and Stage 5 produces a usable Story Video without person-specific motifs
- [ ] Privacy Banner UI surfaces when degraded mode is active
