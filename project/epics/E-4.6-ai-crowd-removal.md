## Goal

Let a user with tourist-site photos full of strangers remove the crowd from selected shots so the artifact is cleaner, building on the A-018 trip cast (which supplies who is "group" and who is "crowd"). Design locked by D-044: a pluggable `CrowdRemover` interface + factory configured via a `crowd_remover_backend` setting — default `remote` (a remote image-editing API does the inpaint; the restart plan's default is the already-routed Gemini image model behind the privacy toggle, landscape §4.3 #24), optional `local` (on-device LaMa/SDXL-class inpainting for capable machines, so no faces leave the device). Edits are opt-in per photo in the refine loop, never auto-applied, kept beside the originals in the snapshot (N-003 immutability), previewed before/after with per-photo accept/reject, disclosed in publish metadata, and surfaced explicitly under ADR-0016 before first remote use.

## Scope

- S-2.9.7 — `CrowdRemover` interface + factory, segmentation mask of non-cast people, opt-in per-photo edit in the refine loop, before/after preview, ADR-0016 disclosure, publish-metadata disclosure, tests with mocked backends

## Out of scope

- Any other generative edit (object removal beyond people, sky replacement, style transfer) — separate v2 epics if ever wanted.
- Auto-applying edits or editing source media in place (N-003 forbids both).
- The per-scene auto grading of E-3.6 (non-generative, Stage 7).
- Generated music (E-4.4) and the multi-agent harness (E-4.2), which the plan parks behind the Trip Package alongside this.

## Acceptance criteria

- [ ] `crowd_remover_backend` selects `remote` (default) or `local`; both implement `CrowdRemover`; backend calls are mocked in tests
- [ ] Non-cast people are masked per photo using the A-018 cast for identity and a person-segmentation model for the mask
- [ ] Edits are opt-in per photo from the refine loop, stored beside the originals in the snapshot, previewed before/after with accept/reject, and disclosed in publish metadata
- [ ] Before the first remote edit the user sees exactly what leaves the device (ADR-0016); the local backend keeps everything on-device and is offered only when the hardware probe (S-3.1.5) says the machine can run it
