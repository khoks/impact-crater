- Stage 6 orchestrator second-guess: Tier-M call returns SecondGuessResult with typed Override list + confidence; auto-applies high-confidence (>0.85) drops/reorders; rest persisted to snapshot for v1 reconfirm UI.
- Stage 9 N-009 thinking step: chooses partial_fix_via_plan_edit (re-runs Stage 5 with brief addendum) or explain_why_not_possible; v1 strategies (full_reprocess, stage_3_rerun, request_user_input) fall back gracefully.

## Goal

Implement Stage 9 **N-009 agentic refinement with custom plan generation** and the Stage 6 **orchestrator second-guess pass with user reconfirm UI**. Snapshot chains via `parent.txt` per N-003. After E-2.7 closes, the user's "more landscape, less faces" type refinement messages produce a meaningfully different result via the orchestrator's thinking-step strategy choice.

This is **M6**.

## Scope

- Stage 6 orchestrator second-guess: Tier-M `orchestrator_second_guess(ArcJudgment, RenderPlan, music_spec, brief)` call producing `SecondGuessResult` with `Override` list + confidence.
- Stage 6 second-guess UI: when `overrides` is non-empty AND `overall_confidence > 0.6`, surface to user via FastAPI websocket; user picks Apply / Skip / Modify-with-NL per override; choices persist on snapshot per [ADR-0011](../../docs/architecture/ADR-0011-curation-engine-algorithm.md).
- Stage 9 agentic refinement (N-009): Tier-M tool-call loop with the 5 strategies (`partial_fix_via_plan_edit`, `partial_fix_via_stage_3_rerun`, `full_reprocess`, `request_user_input`, `explain_why_not_possible`); bounded at 10 turns; cancelable per [ADR-0014](../../docs/architecture/ADR-0014-agent-harness-topology.md).
- Refinement tools wired into the orchestrator's tool registry per [ADR-0014](../../docs/architecture/ADR-0014-agent-harness-topology.md): `re_run_stage_5_with_addendum`, `re_extract_metadata_for`, `re_run_pre_filter_with_overrides`, `request_user_input`, `explain_why_not_possible`.
- Refine UI: enable the previously-disabled "Refine this result" button on the preview screen; clicking opens an NL textarea + submit; orchestrator's thinking-step reasoning logged + surfaced via cost-transparency UI.
- Snapshot chain: new snapshot directory created per refinement; `parent.txt` points at predecessor; multi-snapshot timeline UI surfaces in the project detail view (basic — full multi-version-comparison UI is v1 per A-006).
- `RefinementPlan` persisted at `snapshots/{id}/refinement_plan.json`.
- Failure-mode UX per [ADR-0014](../../docs/architecture/ADR-0014-agent-harness-topology.md): when orchestrator gets stuck (10-turn refinement bound or 50-turn orchestration bound), pause + persist + surface "we got stuck" with continue / abandon / restart actions.
- Telemetry: `OrchestratorTurnEvent` per tool call (tied via `correlation_id`).

## Out of scope

- Manual override (v1; user-edits-plan.json directly is a v1 power-user feature)
- Multi-version artifact comparison UI (v1 — A-006)
- Conversational refinement at scale (v2)
