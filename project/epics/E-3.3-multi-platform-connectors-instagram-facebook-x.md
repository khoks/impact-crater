## Goal

Instagram, Facebook, and X connectors with per-platform formatting (9:16 / 1:1, duration caps) and a watermark/brand-mark mode, on the ADR-0013 connector layer — plus the in-app credential flow (Connect in Settings) that the shipped env-var path lacks, the Facebook photo-album artifact from the original vision, and the MVP-lite auto-captions that publish copy needs.

## Scope

- Connectors: Instagram Reels (Graph API, landed), Facebook Page video (Graph API, landed), X (official API v2, if still wanted).
- Credentials: loopback OAuth → `connector_credentials` (Fernet) with Connect / Disconnect in Settings, starting with YouTube; connector status from DB-or-env.
- Output formatting: 9:16 (Instagram Reels, YouTube Shorts) and 1:1 render targets, duration caps, watermark mode.
- Artifacts: a 20+-photo Facebook album from the same curation pass.
- Publish copy: generated description, hashtags, alt text and an `.srt` sidecar, editable at approve time.

## Out of scope

- Multi-output orchestration (one analysis → N artifacts) — E-3.2 / S-3.2.3. This epic ships single artifact types and connectors.
- Local API hardening (bearer token, origin check, `--allow-remote`) — S-3.11.3 under E-3.11; a hard prerequisite here, not scope.
- In-app OAuth for Meta (Instagram / Facebook Connect) is plan Phase 4 — it reuses the S-3.3.5 pattern but is tracked with the first live Instagram / Facebook posts.

## Dependencies

- Blocked by: S-3.11.3 (local API hardening — per-install bearer token on mutating routes + WebSocket, origin check, refuse non-loopback `--host` without an explicit flag) before S-3.3.5 exposes anything beyond loopback and before any Instagram public media URL exists.
- Blocked by: the OAuth publishing-status decision (plan Phase 1 item 3c — Google OAuth clients in "Testing" issue refresh tokens that expire after 7 days; Production implies verification for the sensitive `youtube.upload` scope) for S-3.3.5.
- Blocked by: the Phase 4 D-NNN that opens I-3 for S-3.3.3 / S-3.3.4 / S-3.3.6 / S-3.3.7 (S-3.3.5 is Phase 1 and runs ahead of it).
- Instagram live posting needs a publicly fetchable HTTPS URL for the MP4 (`IC_PUBLIC_BASE_URL`, `backend/impact_crater/connectors/instagram.py:13-27`); Meta pulls the file, it cannot take bytes inline. For a self-hosted desktop app this means a tunnel or upload host, and the exposed thing must be a single expiring signed media URL, never the API — hence the S-3.11.3 prerequisite.
- Blocks: S-3.2.5 (the per-location Reel needs S-3.3.3's 9:16 target and S-3.3.1 as its publish target); E-4.5 (package publish to ≥ 2 platforms with an audit row per artifact).
